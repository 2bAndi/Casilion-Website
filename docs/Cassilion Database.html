Why now

AI changed what a database is asked to do

Agents read, write and decide, and every step leaves a trail that someone will have to explain later. Six demands follow from that. Most stacks answer them with several products. Cassilion answers them in one.

01

Ingest

Agents, events and sensors write all the time.

A log-structured engine with a durable commit log takes the writes. A write is acknowledged only after the required commit-log synchronisation. TTL and tombstones are part of the data model.

02

Query

Retrieval mixes keywords, meaning, place and relationships.

ZQL covers BM25 text search, exact and approximate vector search, hybrid ranking, spatial predicates and graph traversal. Index results are always reconciled with the authoritative rows.

03

Trace

Someone will ask how an answer came about.

Cross-model queries carry lineage at three levels: none, summary or full. Knowledge-base queries can be explained. Requests emit sampled OpenTelemetry traces.

04

Track

Auditors ask who saw or changed what.

The security audit log is hash-chained and signed per segment. Column-level permissions and masking are checked for every statement and again for every result page.

05

Scale

Data and query volume grow without asking first.

Data is partitioned by token and replicated across nodes and data centres. Nodes join, move, are replaced or decommissioned through staged, controlled topology changes.

06

Survive

Nodes fail, disks corrupt, networks split.

Replication comes with repair and resumable, verified streaming. Corrupt files are detected and quarantined. Backup and restore verify digests before anything is activated.

Consistency

Tunable per request, linearizable where you ask for it

Eight consistency levels from ONE to EACH_QUORUM. Conditional writes such as INSERT … IF NOT EXISTS run on a Paxos protocol and report [applied]. Schema, membership and permissions are ordered by a Raft-backed metadata authority with three or five voters.

Security and longevity

Built for the audit that comes later

Data written today will be read, questioned and attacked for years. These properties are part of the engine, not add-ons.

Post-quantum key exchange

TLS 1.3 everywhere. Traffic between nodes and to the admin API requires mutual TLS with the hybrid X25519MLKEM768 group. A classical fallback for clients must be permitted explicitly and is audited.

Column security in the query

Authorization and masking apply to projections, predicates, ordering, grouping and aggregates. A statement with one unauthorized use is rejected as a whole. Indexes cannot bypass the checks.

Identity from your provider

OAuth access tokens are validated against your issuer. Users and groups are provisioned over SCIM. Emergency access is a dual-custodian, time-limited and audited procedure.

Tamper-evident audit

The security audit is durable, hash-chained and signed per segment. High-impact actions wait until their audit record is admitted.

A durable format with a version

On-disk data uses explicitly versioned, canonical encodings with CRC32C checks and SHA-256-bound manifests. Files are staged and verified before they become visible.

Licences signed twice

Licence files carry a classical ES256 signature and a post-quantum ML-DSA-65 signature. They are verified offline by the cluster.

Hybrid key exchange protects recorded traffic against later decryption. It is not post-quantum peer authentication, and Cassilion makes no FIPS validation claim. The same hybrid group is arriving across the industry, for example in MySQL, MariaDB and Neo4j. Cassilion makes it mandatory between nodes.

Status

What 1.0 is, and what it is not

Cassilion offers bounded, explicit interfaces. We would rather list the limits here than have you find them in production.

Deliberate boundaries

  • No promise of full SQL, CQL, Gremlin or PostGIS compatibility. ZQL is a bounded language.
  • No cross-partition or cross-table transactions. Conditional operations are linearizable within one partition.
  • No general relational joins, window functions or user-defined functions.
  • No online conversion between storage engines. The engine is chosen when the table is created.
  • No mixed clusters with Apache Cassandra and no reading of its SSTables. Cassilion shares the client protocol, not the internals.
  • Prolog without cut, negation-as-failure, dynamic predicates or side effects.
